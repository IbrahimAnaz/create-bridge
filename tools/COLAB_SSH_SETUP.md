# Google Colab SSH Launch & Server Runner Guide

This guide allows you to run the entire **Create Mod Bedrock Bridge** inside a **Google Colab (or Colab Pro)** instance, unlocking:
1. **Direct SSH Access for the Web IDE**: Your remote agent can SSH straight into the Colab Linux VM (`code --remote ssh-remote+...` or `ssh root@...`) to read, write, edit, and run code with 12–53 GB of RAM.
2. **Native Linux Performance**: Full Netty epoll support, fast CPU, and gigabit networking.
3. **Turnkey Automation**: Boots up the 3 services (NeoForge, ViaProxy, Geyser) and exposes Bedrock UDP `19132`.

---

## 1. Google Colab 1-Cell Bootstrap Script

Open a new notebook on [Google Colab](https://colab.research.google.com/) and paste the following snippet into the first cell, then click **Run**:

```python
# ==============================================================================
# CREATE MOD BEDROCK BRIDGE - COLAB HOST & SSH BOOTSTRAP
# ==============================================================================

# 1. Install Java 21, Node.js, and Colab SSH / Tmate
print("[1/5] Installing dependencies (Java 21, Node.js, colab-ssh, tmate)...")
!apt-get update -qq && apt-get install -y -qq openjdk-21-jdk nodejs npm tmate > /dev/null
!pip install -q colab_ssh --upgrade

# 2. Launch SSH Tunnel (Cloudflare - No token required!)
print("\n[2/5] Launching Cloudflare SSH Tunnel...")
from colab_ssh import launch_ssh_cloudflared
launch_ssh_cloudflared(password="createbridge2026")

# Also launch tmate as a fallback direct SSH option (Zero configuration needed)
!tmate -S /tmp/tmate.sock new-session -d
!tmate -S /tmp/tmate.sock wait tmate-ready
print("\n>>> FALLBACK DIRECT TMATE SSH COMMAND: <<<")
!tmate -S /tmp/tmate.sock display -p '#{tmate_ssh}'

# 3. Clone / Setup the repository
print("\n[3/5] Setting up Create Bridge repository...")
%cd /content
!if [ ! -d "create-bridge" ]; then git clone https://github.com/IbrahimAnaz/create-bridge.git; fi
%cd /content/create-bridge

# 4. Verify system diagnostics
print("\n[4/5] Running bridge diagnostics...")
!python3 tools/bridge.py doctor

# 5. Start Background Daemons (NeoForge, ViaProxy, Geyser)
print("\n[5/5] Launching backend daemons in tmux / background...")
!tmux new-session -d -s neoforge "cd /content/create-bridge/headless_server && ./run.sh"
!tmux new-session -d -s viaproxy "cd /content/create-bridge/headless_server/viaproxy && java -jar ViaProxy.jar cli --bind-address 127.0.0.1:25568 --target-address 127.0.0.1:25565 --target-version 1.21-1.21.1"
!tmux new-session -d -s geyser "cd /content/create-bridge/headless_server/geyser && java -jar Geyser-Standalone.jar"

print("\n" + "="*60)
print(">>> ALL SERVICES STARTED IN COLAB! <<<")
print("Web IDE can connect via SSH using the Cloudflare or Tmate command above.")
print("="*60)
```

## 2. Connecting from the Web IDE Agent

The remote agent inside the Web IDE (or VS Code) connects directly via SSH:
1. **Via VS Code Remote SSH**:
   Add the configuration generated by `launch_ssh_cloudflared` to `~/.ssh/config`.
2. **Via Terminal / Direct SSH**:
   Use the printed `tmate` or `ssh` command:
   ```bash
   ssh <session>@nyc1.tmate.io
   ```
3. **Navigate to the workspace**:
   ```bash
   cd /content/create-bridge
   ```

## 4. Connecting Bedrock Minecraft Client to Colab

To allow your Bedrock Minecraft client (on your PC, phone, or console) to join the Colab server over UDP `19132`, run the free **Playit.gg** agent inside Colab:

```bash
curl -SsL https://playit-cloud.github.io/ppa/key.gpg | gpg --dearmor | tee /etc/apt/trusted.gpg.d/playit.gpg >/dev/null
echo "deb [signed-by=/etc/apt/trusted.gpg.d/playit.gpg] https://playit-cloud.github.io/ppa/data ./" | tee /etc/apt/sources.list.d/playit.list
apt-get update -qq && apt-get install -y -qq playit
playit
```
Click the claim URL printed in the Colab output, select **Bedrock (UDP 19132)**, and Playit will give you a public address (`something.gl.joinmc.link`) to type into your Minecraft Bedrock client!
